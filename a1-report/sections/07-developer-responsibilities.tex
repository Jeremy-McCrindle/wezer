\section{Division of Developer Responsibilities}
\label{sec:developer-responsibilities}

WezTerm operates as an informal open-source project led predominantly by its creator, Wez Furlong, and primary maintainer Benoit de Chezelles (@Bew on Github), with development supported by the broader community. Rather than enforcing strict developer roles or formal code ownership, tasks are divided according to contributors' interests, expertise, and willingness to maintain particular areas of the system. 

A significant proportion of the project's overall development responsibility remains with Furlong, who is involved in decisions concerning the system's overall architecture, major changes, and new release planning. The primary maintainer has a stronger coordination role, including integrating changes across the system, identifying important pull requests for Furlong to review, and responding to questions in the discussion boards. General contributors provide much of the remaining development work, from bug fixes and testing to the implementation of new functionality. Contributors also participate in code review and community discussion boards, allowing system knowledge and maintenance roles to be distributed beyond the main developers.

The informal structure of the project allows contributors to specialize in particular architecture subsystems and focus on areas of interest or expertise. WezTerm's modular architecture creates natural boundaries for the division of tasks and since the subsystems have distinct responsibilities and interfaces, developers can make changes within one area without being responsible for the entire system. For example, contributors with limited programming experience in Rust are encouraged to work on smaller UI changes within the GUI frontend, while others can focus on specialized technical areas such as terminal escape sequence handling within the terminal emulation core or the multiplexer pane management system. Contributors who do not wish to focus on code can improve project documentation through the MkDocs-based documentation system or maintain operating system-specific installation instructions. Other contributors are responsible for maintaining WezTerm's distribution and packaging for particular operating systems. Although roles are distributed informally, contributors are expected to maintain the quality and consistency of their own changes. Contributions must include the appropriate tests, comments and documentation, and meet the formatting requirements of the continuous integration system before being submitted as pull requests \cite{contributing}.
